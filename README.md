# 三国地名笺

用今天的中文行政地名，查询 **公元 262 年**的粗略历史格局：既有魏、蜀、吴，也有同时代的西域诸国、东北政权与鲜卑诸部。区分**政权、多个政权、族群 / 诸部**，不把官署设置、朝贡与往来等同于全境占领。原生 HTML、CSS、ES modules；无构建步骤、后端、API 密钥、定位、分析服务或在线地理编码。页面运行资源全部随仓库发布，查询在浏览器中完成。

站点地址：<https://waterwan.github.io/>。根目录 `index.html` 和 `.nojekyll` 可由 GitHub Pages 的 `main / root` 直接发布；不需要自定义 Actions 工作流。

## 使用

输入省、市或区县，可省略普通行政后缀，也可输入完整路径，例如 `江苏省 扬州市 高邮市`、`南京鼓楼区`。同名名称必须选择地区，不做随意子串匹配。上下方向键选择提示，Enter 查询，Escape 关闭提示；同名结果也可用 Tab / Enter 选择。

| 查询 | 页面说明 |

| 天水 / 陇南武都 | 天水参考魏，陇南城市所在地武都参考蜀；不是陇南全域 |
| 贵阳、安顺、毕节、遵义、六盘水 / 铜仁 | 前者所在地参考蜀，铜仁碧江城区参考吴；贵州省给蜀为主、黔东局部吴的分布说明 |
| 凯里市、都匀市、兴义市 | 县级城市的地点条目优先匹配，不被其上级自治州回退覆盖 |
| 黑龙江、西藏 | 三国主要直接控制区之外，而非名称未找到 |

| 库车市、和田市、喀什市 | 分别参考龟兹、于阗、疏勒的所在地或绿洲背景，不代表现行全境 |
| 若羌县 | 古鄯善、扜泥与今县城附近的线索，不覆盖若羌全县 |
| 吐鲁番市 | 交河—高昌附近的车师前部图域参考；曹魏官署另列，不再回退整个新疆集合 |
| 鄯善县 | 车师前部一带的地方线索；突出提醒现代县名不等于古鄯善国中心 |
| 集安市 | 高句丽的国内城—丸都一带，不覆盖今日集安市全域 |
| 吉林市、吉林省 | 市查询参考夫余早期中心；省查询为夫余 / 高句丽等并存背景，不能全省判为一国 |
| 内蒙古 | 鲜卑诸部活动与曹魏北境的背景；诸部不是统一国家 |
| 榆林市、延安市 | 分别提供匈奴诸部、图中“羌胡”统称的区域背景，不再默认整个陕北属魏 |
| 乌鲁木齐、扶余市 | 没有新增单独地点判定，仍明确回退到省域背景，不能以古国同名自动匹配 |
| 南通、滁州 | 已检查但仍有具体地望 / 古地理缺口，不硬判魏吴，也不拿省级并列冒充城市结论 |
| 海南省 | 已识别，但暂不作简单归属判定 |
| 朝阳、鼓楼、长安 | 列出不同省市中的同名地区供选择 |

“长安”按现代区名检索，不作为古代长安的自动别名。“和田”“喀什”“吉林”等也会命中多个现代行政层级，可补上 `市`、`省` 或完整路径。新政权名称没有注入现代名称索引：例如输入 `龟兹` 不会暗中转换为库车，输入 `扶余市` 也不会因古国同名就当成今吉林市的夫余早期中心。当前不支持拼音、繁简自动转换、古地名反查和乡镇街道。

## 本地运行与检查

需要 Node.js 20 或更新版本，**不需要 `npm install`**：

```powershell
npm run dev
# 打开 http://127.0.0.1:4173/

npm test

# 输出全部省级/地级审计的分类统计及仍待补充的名称
npm run audit
# 历史规则变化后，重新生成公开的审计快照
npm run audit:update
```

不要双击 `index.html` 以 `file://` 打开：ES modules 和 JSON 需要 HTTP。开发服务器只监听 `127.0.0.1`，不是部署所需的后端。端口占用时，可在 PowerShell 同一次命令中设置 `$env:PORT = '4174'; npm run dev`。

测试使用 Node 自带的 test runner，覆盖原魏蜀吴地点回归、普通后缀/空格/路径、同名歧义、跨境省份、已知外部/不确定与未知名称的区分、空输入/HTML 样式输入、回退层级、全量名称可达性、历史来源引用及数据校验值。新增测试覆盖西域实体、现代鄯善县辨误、重点城市精度、40 个州 / 地区 / 盟的全区域视角、全部 367 条审计行、图域城市的显式名单，以及由页面实际调用的 `presentHistory()` 所生成的类型、关系、标题、印章和官署联系分离。

`data/coverage.json` 是由实际查询逻辑生成的公开审计，不是另一套人工数量。测试会与现行规则重新计算的结果对比，快照过期则失败。需要完整机器可读输出时使用 `node scripts/audit.mjs --json`。

浏览器验收应另行检查桌面与 360px 手机布局、多实体卡片与长名称换行、主结果不混入官署联系、类型文字、同名辨误提示、方向键/Enter/Tab/Escape、输入法组合输入、同名选择、空/未知输入、加载失败和重试。所有查询文本和实体说明通过 `textContent` 或文本节点输出，不能作为 HTML 执行。页面尊重减少动态效果设置。

## 数据来源与覆盖

### 现代名称

`data/places.json` 是 [modood/Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China) 的 `dist/pca-code.json`，原始字节不变：

- 固定提交：`c49d495b40ac73eb1a66f6eeae5f8fd10696f035`。
- 上游注明的统计快照截止日：**2023-06-30**，发布时间：2023-09-11。提交日期不是区划日期；并非 2026 年实时名录。
- 上游标注来源：国家统计局 2023 年统计用区划代码和城乡划分代码。统计条目不等同于民政正式建制名录。
- 许可：**WTFPL-2.0**，完整文本位于 `licenses/administrative-divisions.txt`；版本、固定下载 URL、SHA-256 见 `data/provenance.json`。
- 港澳台三个省级名称在检索代码中补充，**暂不支持其下级地区**，不声称这些城市或区县已完整收录。

运行时排除 9 个“市辖区 / 县 / 省直辖县级行政区划”等中间分组，将直辖区县接到省级节点；排除县级代码末两位 71—80 的统计管理单元；排除不满/超过 6 位的乡级节点。保留 **34 个省级名称（大陆 31 + 港澳台 3）、333 个大陆地级条目、2,850 个县级名称条目，共 3,217 条**。名称条目中少数仍为统计管理名称，不应拿此数充当正式行政区划统计。

后续改名、新设或辖区调整可能尚未收录。没有地理坐标，也没有借助外部服务推测用户位置。

### 全国覆盖审计与实际缺口

当前版本**逐条审计全部 34 个省级、333 个地级名称**，共 367 行，类别如下。行政名称覆盖仍是 3,217 条，不能把它当作独立历史考证数量。

| 依据类别 | 省级 | 地级 | 含义 |
| --- | ---: | ---: | --- |
| 直接地点资料 | 0 | 20 | 有政府沿革等地点资料，仍受具体范围与年代限制 |
| 年代图域参照 | 0 | 223 | 明确的城市 / 分图关系，非上级省默认，也非逐城地方志核验 |
| 整区域综述 | 34 | 41 | 保持整个省、州 / 地区 / 盟视角；41 中另含榆林的区域资料说明 |
| 上级粗推 | 0 | 47 | 尚无独立地点判定，显示“本地独立资料待补”及上级参考 |
| 已检查仍有证据缺口 | 0 | 2 | 南通古海岸 / 成陆、滁州前线地望，未硬判为一国 |

原 9 个只有年代地图依据的城市锚点计入图域类，**没有冒计为直接地方资料**。全部 40 个自治州 / 地区 / 盟都有独立的整区域综述，绝不静默把行政驻地当作全域。共配置 298 条明确地点 / 区域规则，包含 50 条特别地点或待核说明、12 个独立县级地点条目；这两个子数不是“全部直接考证通过”的数量。

剩余 47 个地级上级回退具体为：大同；乌海、呼伦贝尔、巴彦淖尔；丹东、营口、盘锦、铁岭；四平、辽源、松原、白城；黑龙江的 12 个地级市；舟山；东营；珠海、汕头；百色；海南的 4 个地级市；西藏的 6 个地级市；庆阳；银川、石嘴山、吴忠、中卫；乌鲁木齐、克拉玛依、哈密。不是说它们历史上必然多国或不可知，而是**本库未完成足够可靠的本地对应**。省级海南继续保留不确定。

省级需更多材料的审计标记为 2 条：海南尚不作简单归属判断；重庆已明确列出主城区蜀地、巫山吴地，但其余辖区与现代县界仍需细分。重庆的已知吴地例外依据[渝中区地望资料](https://www.cqyz.gov.cn/zjyz/yzgk/lsyg/202302/t20230223_11646245.html)、[重庆地方志的巫山沿革](https://dfz.cq.gov.cn/zqlswh/rwby_417819/202602/t20260209_15397922.html)及 262 年益州北部 / 吴荆州分图说明，不以泛称“边界不确定”替代已知分布。

加上 40 个仍需进一步地域细分的州 / 地区 / 盟综述，以及南通、滁州，审计共标出 **89 个地级条目需要更多材料或更细分区**。这不否定已有的明确代表地域，也不是把全部 89 条说成史学争议。完整名称、当前实际证据来源、范围、类别和限制由 `npm run audit` 和 `data/coverage.json` 给出。

规则顺序为：具体地方条目优先，其次是明确列出的图域 / 全区域条目；没有本条依据时才查上级，最后才用省域背景。**回退改变的是参考来源，不会提高证据等级。** 页面明确显示“上级参考 · 本地未单独核验”、实际依据与范围。例如丰满区回退到吉林市的东团山—南城子一带，不能变成全区已核验；和田地区则有整区域说明，不会把下辖和田市的锚点升级成全地区。即使直接命中条目，也只说明记录中限定的范围。

省域背景允许单一主要势力、多国、多类实体并存、边地 / 部分区域、三国主要直接控制区之外、暂不确定。“西域诸国并存”是集合标题，列出的是代表性政权而非穷尽名单；车师合称标记为多个政权，与单列的车师前部不是同一层次。鲜卑诸部是族群 / 部众，不是统一国家，也不能将族群活动当作国界。

**关系与归属分开**：曹魏的西域长史、戊己校尉，以及文献中的朝贡往来，在独立的“官署与往来，不等于全境占领”区域展示，不进入主归属标题或印章。并不反向断言所有西域诸国都完全独立或完全直属。省、州、郡、县不是跨时代不变的空间单位；古代州郡界也不是国家疆界。

西藏等尚无可靠具体映射的地区仍可显示“三国主要控制区之外”，海南等仍保留不确定；这不同于名称未知，也不是否定当地存在自身历史。本轮不扩充所有边地或世界各政权，更不把后来出现的吐蕃、突厥、回鹘、高昌王国挪到 262 年。出现“高昌”官署线索不等于已存在后世的高昌王国。

本项目是教育性的粗略参考，**不是逐点历史 GIS、精确行政对照、全境实控断言或现代疆域立场表达**。

## 扩充维护

- 历史实体先登记于 `ENTITIES`，注明 `name`、印章短名 `short`、`type`（`polity` / `polities` / `peoples`）及现有 `tone`。实体目录不是现代地名别名表，也不是有精确疆界的国家清单。
- 地点条目以现代名称库中的代码为键，加入 `LOCAL_RULES` 或 `EXTRA_RULES`；图域城市加入 `MAP_CITY_GROUPS` 的显式代码 / 名称名单；州 / 地区 / 盟使用 `REGIONAL_REVIEWS`，不能放进城市中心清单。`entities` 数组逐条写 `{ id, relation, note }`；`relation` 为 `affiliation`（区域归属参考）、`regional`（区域背景）、`activity`（活动线索）或 `contact`（官署 / 往来）。多个政权或族群不可使用单国式 `affiliation`，联系项单列。
- 注明 `evidence`（`locality` / `city-core` / `historic-site`）、固定年代、限制及 `sources`。`historic-site` 必须明确 `scope` 与 `dateNote`，其余有跨时期材料的条目也应写明年代精度。多方并存使用 `kind: "coexistence"` 和概括性的 `headline`，不要串成长长的“统一国家名”。有古今同名误导风险时使用 `nameNote` 作醒目提示。
- 新增史料放入 `SOURCES`，使用可查证的出处和真实 URL。不得编造引文、县界或细化到资料不能支持的层次。
- 省域背景修改在 `PROVINCE_RULES`。无充分材料时保留多国 / 边地 / 不确定，不用任何单一政权或族群作默认值消除空白。
- `basis` 明确设为 `locality`（地点资料）、`atlas`（图域参照）、`regional`（整区域综述）、`gap`（已检查仍有缺口）。不能为了让统计变好而把默认继承改名为核验。`coverageGap` 标记区域内部还需细分；缺口原因写入 `gapReason` 和可读说明。
- 展示层在 `js/presentation.js`，审计在 `js/coverage.js`，页面、脚本和 Node 测试共用。数据变动后运行 `npm run audit:update`、`npm test`，同步更新本节数量和剩余缺口。新增类型、关系或状态时同步更新映射与样式，确保联系不能变为归属，长标签在手机上可换行。
- 名称匹配在 `js/lookup.js`。保留精确名称优先、完整路径和歧义列表；增加别名时也要测试是否造成重名，不能悄悄挑第一项。
- 更新名称数据时同时更新 `data/provenance.json` 的固定提交、实际快照日期与校验值；核查上游许可、筛选规则和实际计数，再更新测试、README 和页面覆盖说明。不要把提交日期标成数据快照日期。
- 为新增具体判断补充测试，尤其是边界地区、城市中心与下辖区县之间不能越级继承的案例。
