# 三国地名笺

用今天的中文行政地名，查询 **公元 262 年**的魏、蜀、吴粗略区域背景。原生 HTML、CSS、ES modules；无构建步骤、后端、API 密钥、定位、分析服务或在线地理编码。页面运行资源全部随仓库发布，查询在浏览器中完成。

站点地址：<https://waterwan.github.io/>。根目录 `index.html` 和 `.nojekyll` 可由 GitHub Pages 的 `main / root` 直接发布；不需要自定义 Actions 工作流。

## 使用

输入省、市或区县，可省略普通行政后缀，也可输入完整路径，例如 `江苏省 扬州市 高邮市`、`南京鼓楼区`。同名名称必须选择地区，不做随意子串匹配。上下方向键选择提示，Enter 查询，Escape 关闭提示；同名结果也可用 Tab / Enter 选择。

示例：

| 查询 | 页面说明 |
| --- | --- |
| 高邮 | 曹魏区域参考；约 224 年前后县废，不声称 262 年仍存在同名县 |
| 扬州 | 城市中心一带参考魏；不把现代城市混同于古代扬州 |
| 南京、成都 | 分别以建业、成都城市中心作为吴、蜀的锚点 |
| 西安市、陕西西安 | 长安一带参考魏；仅输入“西安”会因其他城市的西安区而出现选项 |
| 洛阳、汉中、杭州、广州、襄阳 | 分别参考魏、蜀、吴、吴、魏，均注明城市中心尺度 |
| 江苏、安徽、湖北 | 魏 / 吴多国背景，不返回无条件的单国全境结论 |
| 陕西 | 魏 / 蜀背景，汉中不被并入魏 |
| 南京鼓楼、宝应 | 明示“未单独核验”，只提供上级城市中心背景，不能视作区县结论 |
| 合肥 | 暂无独立条目，明确回退到安徽省域背景，保留魏 / 吴两种范围 |
| 黑龙江、西藏 | 三国主要直接控制区之外，而非名称未找到 |
| 新疆、海南省 | 已识别，但暂不作简单归属判定 |
| 朝阳、鼓楼、长安 | 列出不同省市中的同名地区供选择 |

“长安”按现代区名检索，不作为古代长安的自动别名。当前不支持拼音、繁简自动转换、古地名反查和乡镇街道。

## 本地运行与检查

需要 Node.js 20 或更新版本，**不需要 `npm install`**：

```powershell
npm run dev
# 打开 http://127.0.0.1:4173/

npm test
```

不要双击 `index.html` 以 `file://` 打开：ES modules 和 JSON 需要 HTTP。开发服务器只监听 `127.0.0.1`，不是部署所需的后端。端口占用时，可在 PowerShell 同一次命令中设置 `$env:PORT = '4174'; npm run dev`。

测试使用 Node 自带的 test runner，覆盖核心地点、普通后缀/空格/路径、同名歧义、跨境省份、已知外部/不确定与未知名称的区分、空输入/HTML 样式输入、回退层级、全量名称可达性、历史来源引用及数据校验值。

浏览器验收应另行检查桌面与 360px 手机布局、方向键/Enter/Tab/Escape、输入法组合输入、同名选择、空/未知输入、加载失败和重试。所有查询文本通过 `textContent` 或文本节点输出，不能作为 HTML 执行。页面尊重减少动态效果设置。

## 数据来源与覆盖

### 现代名称

`data/places.json` 是 [modood/Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China) 的 `dist/pca-code.json`，原始字节不变：

- 固定提交：`c49d495b40ac73eb1a66f6eeae5f8fd10696f035`。
- 上游注明的统计快照截止日：**2023-06-30**，发布时间：2023-09-11。提交日期不是区划日期；并非 2026 年实时名录。
- 上游标注来源：国家统计局 2023 年统计用区划代码和城乡划分代码。统计条目不等同于民政正式建制名录。
- 许可：**WTFPL-2.0**，完整文本位于 `licenses/administrative-divisions.txt`；版本、固定下载 URL、SHA-256 见 `data/provenance.json`。
- 港澳台三个省级名称在检索代码中补充，**暂不支持其下级地区**，不声称这些城市或区县已完整收录。

运行时排除 9 个“市辖区 / 县 / 省直辖县级行政区划”等中间分组，将直辖区县接到省级节点；排除县级代码末两位 71—80 的统计管理单元；排除不满/超过 6 位的乡级节点。保留 **34 个省级名称（大陆 31 + 港澳台 3）、333 个大陆地级条目、2,850 个县级名称条目，共 3,217 条**。名称条目中少数仍为统计管理名称，不应拿此数充当正式行政区划统计。

后续改名、新设或辖区调整可能尚未收录。没有地理坐标，也没有借助外部服务推测用户位置。

### 历史材料与方法

1. [《中国三国时期历史地图》](https://osgeo.cn/map/m0346/)：明确采用魏景元三年、蜀汉景耀五年、吴永安五年，即 **262 年**。仅链接作为阅读参考，**未复制受版权保护的扫描图，也未使用或假称获取精确矢量边界**。
2. [高邮市人民政府《历史沿革》](https://gaoyou.yangzhou.gov.cn/mlgy/gygk/art/2023/art_0e6f92a8aabf4866a7f571c3911d8552.html)：支持三国初期属曹魏徐州广陵郡、约 224 年前后县废的线索。早期沿革与固定年代地图交叉使用，只作今高邮一带参考，不能证明现代高邮市全境或 262 年同名县建制。

历史规则写在 `data/history.js`，与名称库分开。首版有 **34 条省域背景、9 条城市中心锚点和 1 条高邮地方线索**，并没有逐一考证全国 2,850 个县级条目。所有具体文字是本项目的谨慎概述，不伪造来源引文。

规则顺序为：本条地方/城市记录 → 上级城市中心背景 → 省域背景。**回退改变的是参考来源，不会提高证据等级。** 页面明确显示“上级参考 · 本地未单独核验”、实际证据层级与实际参考范围。即便直接命中城市记录，也只说明城市中心附近，不给全市范围盖章。

省域背景允许单一主要势力、多国、边地/部分区域、主要直接控制区之外、暂不确定。省、州、郡、县不是跨时代不变的空间单位；古代州郡界也不是魏蜀吴国界。东北、西域、高原与海岛等区域不因存在间接联系、征伐或名义设置，就被强行判为某国全部实控。

本项目是教育性的粗略参考，**不是逐点历史 GIS、精确行政对照、全境实控断言或现代疆域立场表达**。

## 扩充维护

- 新的历史条目以名称库中的稳定代码为键，加入 `LOCAL_RULES`；注明 `evidence`（`locality` 或 `city-core`）、固定年代、范围、限制及 `sources`。先确认史料支持 262 年附近的判断，勿只凭现代省份或古代州名推断。
- 新增史料放入 `SOURCES`，使用可查证的出处和真实 URL。不得编造引文、县界或细化到资料不能支持的层次。
- 省域背景修改在 `PROVINCE_RULES`。无充分材料时保留多国/边地/不确定，不用“默认魏/蜀/吴”消除空白。
- 名称匹配在 `js/lookup.js`。保留精确名称优先、完整路径和歧义列表；增加别名时也要测试是否造成重名，不能悄悄挑第一项。
- 更新名称数据时同时更新 `data/provenance.json` 的固定提交、实际快照日期与校验值；核查上游许可、筛选规则和实际计数，再更新测试、README 和页面覆盖说明。不要把提交日期标成数据快照日期。
- 为新增具体判断补充测试，尤其是边界地区、城市中心与下辖区县之间不能越级继承的案例。
